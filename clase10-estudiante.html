CRUD es el acrónimo de las cuatro operaciones básicas sobre datos en una base de datos: Create (crear, con INSERT), Read (leer, con SELECT), Update (actualizar, con UPDATE) y Delete (eliminar, con DELETE).

UPDATE: modificar filas que ya existen

UPDATE cambia el valor de una o más columnas en las filas que cumplen una condición. La estructura es UPDATE tabla SET columna = valor WHERE condicion;. Sin la cláusula SET, MySQL no sabe qué cambiar; sin la cláusula WHERE, cambia esa columna en todas las filas de la tabla, no solo en la que ustedes querían.

Ejemplo sobre el proyecto de Gestión de biblioteca: cuando un estudiante devuelve un libro, no se crea una fila nueva — se actualiza la fila existente del préstamo.

UPDATE prestamo SET estado = 'devuelto', fecha_devolucion = '2026-09-03' WHERE id_prestamo = 14;

Por qué el WHERE en UPDATE no es opcional

Si alguien ejecuta UPDATE articulo SET estado = 'dado de baja'; sin WHERE, todos los artículos del inventario quedan marcados como dados de baja, no solo el que se quería retirar. MySQL no pregunta ni avisa: ejecuta exactamente lo que se escribió.

Ejemplo correcto sobre el proyecto de Gestión de inventarios, retirando un solo artículo:

UPDATE articulo SET estado = 'dado de baja' WHERE id_articulo = 7;

Buena práctica: antes de un UPDATE, ejecuten primero un SELECT con la misma condición del WHERE, para ver exactamente qué filas van a cambiar antes de cambiarlas.

DELETE: eliminar filas completas

DELETE FROM tabla WHERE condicion; elimina filas enteras, no valores de columnas. Igual que con UPDATE, omitir el WHERE borra todas las filas de la tabla — y a diferencia de UPDATE, no hay forma de recuperar los datos borrados si no había una copia de seguridad.

Ejemplo sobre el proyecto de Gestión comportamental: eliminar una observación que se registró por error y que el docente anuló:

DELETE FROM observacion WHERE id_observacion = 22;

DELETE y las llaves foráneas: por qué a veces MySQL se niega a borrar

Si una tabla tiene una llave foránea apuntando a otra, MySQL no deja borrar la fila "padre" mientras existan filas "hijas" que dependan de ella — es la misma protección de integridad referencial que exige que un INSERT apunte a una fila que sí existe. En el proyecto de Gestión Asistencia y Permisos, no se puede borrar un estudiante de la tabla estudiante si esa persona ya tiene registros en asistencia o en permisos: MySQL responde con un error de restricción de llave foránea.

-- Esto falla si el estudiante tiene registros relacionados: DELETE FROM estudiante WHERE documento = '1017123456'; -- Error: Cannot delete or update a parent row: a foreign key constraint fails

Esa restricción no es un defecto: protege la base de datos de quedar con registros de asistencia huérfanos, sin estudiante al que pertenecerle. Si de verdad hay que borrar al padre, primero se borran (o reasignan) las filas hijas relacionadas.
