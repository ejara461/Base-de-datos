Lenguaje SQL y CREATE TABLE

Siete lecturas y tres ejercicios interactivos, con el caso de chef, receta e ingrediente para no adelantar el taller 2.

Lectura 1

SQL tiene partes distintas

SQL no es un solo lenguaje homogéneo: se divide en sublenguajes según lo que hacen sus instrucciones. Hoy trabajamos con DDL (Data Definition Language): las instrucciones que definen la estructura de la base de datos, como CREATE, ALTER y DROP. El DML (Data Manipulation Language) — SELECT, INSERT, UPDATE, DELETE — llega en las clases 9 y 10, cuando ya haya tablas donde guardar datos.

Lectura 2

Así se ve phpMyAdmin

phpMyAdmin es la página que XAMPP activa para administrar MySQL sin escribir comandos en una terminal. Al entrar (normalmente en http://localhost/phpmyadmin), a la izquierda aparece un panel con la lista de bases de datos que ya existen en el servidor. Arriba de esa lista hay un enlace para crear una base nueva: escribir el nombre ahí y confirmar hace lo mismo que CREATE DATABASE, solo que sin escribir el comando.

Al entrar a una base de datos —clic sobre su nombre en el panel izquierdo— arriba aparecen varias pestañas: Estructura, SQL, Buscar, Exportar, entre otras. La pestaña SQL abre un cuadro de texto grande: ahí se pega el CREATE TABLE completo, y un botón debajo del cuadro (dice "Continuar" o "Ejecutar" según la versión instalada) lo ejecuta. Si el script tiene un error de sintaxis, phpMyAdmin lo señala en rojo con el mensaje real del motor MySQL, no con una alerta genérica.

La pestaña Estructura de una base de datos, una vez ejecutado el script, lista las tablas creadas. Al entrar a una tabla específica, esa misma pestaña muestra columna por columna: nombre, tipo de dato, si acepta nulos y cuál es la llave primaria. Ahí se comprueba, sin volver a escribir SQL, que la tabla quedó como se pensó.

Lectura 3

CREATE DATABASE: un espacio por proyecto

Antes de crear tablas hace falta un contenedor. CREATE DATABASE nombre; crea ese espacio; USE nombre; le dice al motor en cuál trabajar de ahí en adelante. Cada proyecto PIA tiene su propia base de datos, no se comparte una sola entre los cinco.

CREATE DATABASE IF NOT EXISTS bd_cocina_ejemplo; USE bd_cocina_ejemplo;
Lectura 4

CREATE TABLE: columnas y tipos de dato

Cada columna del modelo relacional (clase 6) se convierte en una línea de la tabla: nombre de columna, tipo de dato, y si es obligatoria (NOT NULL). Los tipos más usados en los cinco proyectos son INT (números enteros), VARCHAR(n) (texto de largo variable, hasta n caracteres), DECIMAL(p,d) (dinero y cantidades con decimales), DATE y DATETIME (fechas).

Lectura 5

Llave primaria y AUTO_INCREMENT

PRIMARY KEY marca la columna que identifica cada fila sin ambigüedad — el mismo identificador subrayado del diagrama de Chen. Cuando esa columna es un número que el motor asigna solo, se agrega AUTO_INCREMENT. No siempre hace falta: si la clave natural ya es única y estable (un número de documento, por ejemplo), se puede usar directo como llave primaria, sin autonumérico.

Lectura 6

Llave foránea: conectar tablas

FOREIGN KEY (columna) REFERENCES otra_tabla(columna) es la traducción directa de la flecha del modelo relacional. Una consecuencia práctica: MySQL exige que la tabla referenciada ya exista antes de crear la que la referencia. Por eso el orden de los CREATE TABLE no es libre: primero van las tablas "independientes", después las que dependen de ellas.

CREATE TABLE chef ( id_chef INT AUTO_INCREMENT PRIMARY KEY, nombre VARCHAR(60) NOT NULL, apellido VARCHAR(60) NOT NULL, telefono VARCHAR(20), especialidad VARCHAR(60) ); CREATE TABLE receta ( id_receta INT AUTO_INCREMENT PRIMARY KEY, nombre_receta VARCHAR(100) NOT NULL, tiempo_preparacion_minutos INT, id_chef INT NOT NULL, FOREIGN KEY (id_chef) REFERENCES chef(id_chef) );
Lectura 7

De la tabla normalizada al CREATE TABLE

Cada columna que sobrevivió a la normalización de la clase pasada se traduce, una por una, sin agregar columnas que no estaban ahí. Si al escribir el CREATE TABLE su grupo se da cuenta de que hace falta una tabla que no existía en el modelo — como puede pasarle a cualquier proyecto al pasar de lo conceptual a lo real — no la inventen en silencio: coméntenlo con el docente antes de seguir.

Ejercicio 3 · Detective de sintaxis

Cada fragmento tiene o no tiene un error. Márquelo.

CREATE TABLE receta ( id_receta INT AUTO_INCREMENT PRIMARY KEY nombre_receta VARCHAR(100) NOT NULL );
Falta la coma entre id_receta ... PRIMARY KEY y nombre_receta .... Cada columna se separa con coma.
CREATE TABLE receta_ingrediente ( id_receta INT, id_ingrediente INT, cantidad DECIMAL(6,2), FOREIGN KEY (id_receta) REFERENCES receta(id_receta) );
No tiene PRIMARY KEY. Con llave compuesta hace falta PRIMARY KEY (id_receta, id_ingrediente).
CREATE TABLE chef ( id_chef INT AUTO_INCREMENT PRIMARY KEY, nombre VARCHAR(60) NOT NULL );
Correcto: PK autonumérica, columna obligatoria, sintaxis completa.
